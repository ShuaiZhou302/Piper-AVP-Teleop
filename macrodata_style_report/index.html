1. 为什么要标子任务

高层指令（「做一道菜」「整理桌面」）对机器人学习往往太粗。子任务标注回答两件事： 这一刻在做什么，以及 上一个动作在哪结束、下一个从哪开始。 Macrodata 的 WGO-Bench 把这件事变成可迭代的 benchmark；我们用其中最难的 egocentric 子集 HomER， 在自有 EgoVid 管线 + 本地/隧道 Qwen 上做可复现消融。

本报告范围：HomER 25 episodes · 470 gold segments · 主指标 Segment F1@0.75（outer snap, micro）/ 固定边界 LLM-judge Acc / Semantic E2E F1。不重跑实验；数字来自已落盘的 V5.1 / Expert 包。

3. 三个指标怎么算（含玩具 walkthrough）

3.1 Segment F1 —— 只考时间切得准不准

P = 配成功数 / 预测段数；R = 配成功数 / gold 段数； F1 = 2PR/(P+R)。越大越好，最大 1.0。

3.2 固定边界 Annotation Accuracy

时间用 gold；模型只写句子；judge 判断是否同一完成事件。Acc = 判对段数 / 470。

3.3 Semantic E2E F1

先做时间配对，再对配对成功的 pair 做语义 judge；两边都过才计入 semantic match，再算 F1。

玩具例子（与 scorer 一致）

Gold：G0[0,3], G1[3,6], G2[6,10] · Pred：P0[0.5,2.8], P1[2.8,5.5], P2[5.5,8], P3[8,9.5]

  1. Outer snap：P0.start→0，P3.end→10
  2. IoU：P0–G0≈0.933，P1–G1≈0.781（其余 <0.75）
  3. Greedy 1-1：n_match=2
  4. P/R/F1：P=2/4=0.50，R=2/3≈0.67，F1≈0.571

标注例子：gold=pick up the red cup and place it on the shelf， pred=place red cup onto shelf → judge 通常 match=true（同动词族+物体+目标）。 这不是规则 parse，是再调一次 LLM。

4. Contact sheet 是什么

按固定时间间隔（我们跟 blog 一样约 0.5 秒）抽帧，缩成约 224px 小图， 按时间顺序拼成一张「联系表」（约 20 格/张），格子上画可视时间戳。 模型看着这张拼图输出各段起止秒数——不必把整段视频当 MP4 喂进去。

名词速查

  • 整集一次：该集所有 sheet 尽量一次塞进 API，避免窗口接缝假切点。
  • GEPA：用自动 prompt 搜索得到的规则集（completed events + duration prior），不是新模型。
  • S1 反欠分割：催模型多切短段，抬召回，易过分割。
  • S2 二次精修：粗分后再对局部窗精切；full-cover + pad=0 是最强分段。

5. Part I：分段消融

目标：在没有 Gemini 主线的前提下，逼近 HomER 合理天花板，并弄清每一步改动的真实贡献。

Segment F1@0.75（HomER micro）

条件F1P / Rmatch/pred/gold模型n_ep备注

叙事：我们怎么走到 0.203

  1. 原 EgoVid：腕速启发式 + merge → F1≈0.095，pred 810，过分割。
  2. Contact sheet 分片（max3）：外形像 blog，但接缝假切；397B≈0.095，27B≈0.128。
  3. 整集一次：去掉分片；欠分割出现（pred 变少）。
  4. GEPA prompt：只标完成事件 + 时长先验 → aligned 0.1369（约 0.137）。
  5. S1 / 早期 S2：抬召回，F1 到 0.156 / 0.167，但仍碎。
  6. S2 pad=0 full-cover：局部短窗覆盖粗段再切 → 0.2031（当前最强分段）。
  7. Gemini 2.5 Flash API：同 HomER 上约 0.072，未超过开源最强（实现/空预测问题并存）。
分段结论：视觉外形对齐 blog 不够；整集一次 + GEPA + S2 full-cover 才是开源侧主升力。 模型仍重要，但「换更大/更贵」不等于自动涨（flash API 反例；27B 分片曾优于 397B 分片）。

8. 失败模式与教训

  • 分片 contact sheet会在人工切窗处造边界；整集一次更稳。
  • 欠分割 vs 过分割：GEPA 后 pred 偏少；S1 猛催会切碎；S2 full-cover 是更好的折中。
  • 照搬 blog 视觉输入不等于涨分：邻段 sheet、糙 hand-collage 在 Qwen 上掉点。
  • centerproxy / 光流 overlay不能冒充真 hand crop；审计里标红过。
  • 「测试太快」：多数全量是高并发真跑；但 expA_raw 曾整目录复制未重标——要以 API 次数与文案 diff 为准。
  • 换 API 模型不是免费午餐：gemini-2.5-flash 在我们 HomER 设定下未超过开源最强。
  • Judge 口径会改变 Acc；汇报时要固定 judge 再比模型。
